# Synthetic data generation assumptions

This note describes the main scenario settings used by `script/generate_synthetic_data.py`. The values are simulation design choices, not estimates of actual Kenyan pharmacy operations.

## Scenario scope

- Business: a fictional Kenyan pharmacy retailer.
- Period: 1 January to 31 December 2025 (365 days).
- Branches: 12 fictional stores, arranged as two branches in each of six counties: Nairobi, Mombasa, Kisumu, Nakuru, Kiambu and Uasin Gishu.
- Product catalogue: 150 generic medicine and healthcare-supply product labels.
- Customers: 8,000 pseudonymous synthetic customer records.
- Sales attempts: 100,000 transaction headers.
- Currency: KES.
- Customer identification: 80% target share of transaction headers linked to a customer ID; the remaining records represent unidentified buyers.

## Main generator settings

The script uses NumPy's random generator with `SEED = 20250101`. Keeping the seed unchanged is intended to reproduce the same synthetic outputs in a compatible Python, NumPy and pandas environment.

| Setting | Value | Interpretation |
|---|---:|---|
| `N_TXN` | 100,000 | Number of simulated sales attempts |
| `N_CUST` | 8,000 | Number of synthetic customer records |
| `ID_SHARE` | 0.80 | Target share of sales attempts assigned an identified customer |
| `P_VOID_RANDOM` | 0.013 | Random cashier-void probability parameter |
| `P_RETURN` | 0.0105 | Return-event probability parameter for completed transactions |
| `REVIEW_DAYS` | 14 | Simulated inventory reorder review cycle |
| Product-level promotions | 40 | Number of simulated product-level promotions |
| Category-level promotions | 20 | Number of simulated category-level promotions |
| `N_PRICE_CHANGES` | 30 | Number of products selected for a simulated price/cost change |
| `N_WRITEOFFS` | 2,500 | Write-off event parameter |
| `N_ADJUST` | 2,500 | Inventory adjustment event parameter |

The generator contains additional distributions and business rules for transaction timing, product popularity, branch weights, customer segments, discounts, returns, stock receipts, stock-outs and purchasing. Refer to the code for the exact implementation.

## Important interpretation notes

- Branches, customers, suppliers, sales, prices, costs, promotions, purchase orders and inventory movements are fictional.
- Product names are generic medicine and healthcare-supply labels. The generator does not currently cite a specific catalogue used to compile the labels; their provenance should be documented separately before presenting them as sourced catalogue data.
- Public CPI and holiday datasets in `data/Public_data/` are maintained separately and are not generated by this script.
- The script also creates a blank CPI template and an unverified holiday draft under `data/raw/public/`. These are placeholders only and should not be used as verified public context.
- The simulation can be used to demonstrate data engineering, retail analysis and forecasting workflows. It cannot establish actual market demand, customer behaviour, pharmacy profitability or real-world model performance.
